# 研究读数（Phase 3B 领域集成）

本轮把安全领域（MAL/coreLang、CAGE 4、受控本地服务）接入通用实验平台，形式化闭环与红蓝/准入/修订机制在真实上游工具上跑通。方法来源见 [reuse-ledger.md](reuse-ledger.md) 第 4 节；保证范围见 [assurance-scope.md](assurance-scope.md)。

## 1. 问题

把现成的攻击语言（MAL/coreLang）、原生网络防御仿真（CAGE 4/CybORG）与一个受控业务服务接入同一平台，使它们能：导入、形式化检查、运行红蓝策略、按合同准入副作用动作、在可比较状态上做模型修订，并与模拟器交叉核对——同时如实区分模型内结论、实测、预测偏差、信息假设与未覆盖能力。

## 2. 方法与发现

- **原生可达集作为降低预言**（D1）：把 MAL 攻击图的确定性子集降低到既有有限 IR 时，结构化不动点会因 mal-simulator 剪枝“不必要”步骤而过近似（实测 77 vs 原生 64）。改以**原生模拟器可达集为 fold 预言**，让 IR 闭包精确复现原生对目标的可达性，再由参考解释器与 Z3 独立复核（三引擎一致）。存在步与已禁用防御按原生真值折叠。
- **准入=执行门控，保证=检查范围**（D2）：把领域准入实现为 G2 的 `EXECUTION_GATE`，直接继承“拒绝零副作用”并覆盖 local runner / Temporal / 重发 / 重执行。验证凭据的**签名只提供来源与完整性，数学保证等于凭据记录的检查范围**；对弱检查签名不会使其变强，模型 RELEASED 标签本身不构成准入。三值条件让“未知”可与“违规”区分（未知触发重观测/重规划）。
- **三类意图分离**（D1–D2）：LabPolicy（实验边界）、TargetSecurity（目标性质）、BusinessSLO（业务目标）各自解释。红方寻找 TargetSecurity 反例是实验成功，**不是**违反 LabPolicy——这是领域集成最易混淆处，机制上分开。
- **蓝方=回合前配置（最小割）**（D3）：引擎以候选集判定“无可用动作”，回合式防御需要“跳过”语义；把蓝方建成回合前的最小代价割（最大流最小顶点割）配置选择，既真实（防御是配置决策）又避免改内核。对最小模型割集大小=1 即阻断全部红方基线。
- **模型修订的真实/陈旧之分**（D3）：沿用 D-022，可比较状态上的真实偏差才产生回归案例与修订；陈旧观测差异不入回归库。
- **原生分数与平台指标分开**（D5）：CAGE 每队奖励是 CybORG 自己的量纲，与平台可达性、服务成功率不可互换；跨 MAL/CAGE/本地探针只核对方向（红方存在恶化防御目标），不合并量纲。小样本用于工程验收，均值/方差与样本量如实报告。

## 3. 工程取舍

- **隔离优先于合并**：MAL/CAGE 依赖与冻结锁冲突，装在独立 venv 经类型化子进程调用（D-023 同模式），绝不进入平台环境。CAGE 只装脚本基线所需核心依赖，跳过 torch/ray 以省数 GB 磁盘。
- **签名用 stdlib hmac**：避免给冻结锁新增编译依赖（`cryptography`），HMAC-SHA256（FIPS-198）满足“来源+完整性”的定位；`Signer`/`Verifier` 抽象可换非对称后端。
- **方法只借概念不 vendoring**：Shielding / AgentSpec / Progent / VeriGuard / ARTEMIS / Dynamic Cyber Ranges 作为方法参考自实现，不引入其代码与许可（reuse-ledger 第 4 节）。

## 4. 局限与后续

- 真实 LLM 端点（混合策略）、CAGE RL 训练智能体（torch/ray）、PRISM-games 领域概率绑定为条件项/备选清单，未在本环境执行，不冒充交付。
- MAL 的其它语义（TTC、随机、部分观测、数量奖励）超出确定性 profile；蓝方加固是 MAL 防御的 IR 级抽象，具体 coreLang 防御语义另行声明。
- 带镜像发行与去重离线包受宿主磁盘保留量限制（见 acceptance-phase3.md），在更空磁盘上可补跑。
