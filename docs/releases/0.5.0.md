Phase 5–8 of formal-agent-lab: a verifier-grounded **research track** on top of the phase-4 platform — model↔program conformance, real provider calls with raw-answer capture and paired evaluation, held-out cases, and a security domain rebuilt around **real attack models and real CVEs**. Every result below comes from a check that actually ran; evidence files carry the revision they were produced at.

## Highlights

**Research foundation (Phase 5–6)**
- **Model ↔ program conformance (5A/5B):** a research-case format (sealed artifacts + case digest), an import validator (property/version match, missing observations, stale evidence, data-separation: a reference answer may never be a task input, offline read from a zip), and conformance scoring that recomputes a reference verdict from a recorded run (belief DEVIATES / revision CORRESPONDS / UNKNOWN). Tenant-isolation case included.
- **Provider calls and evaluation (6A/6B):** a research adapter for two provider protocols with raw-response-first recording, visible-refusal / content-filter / empty / truncated / invalid-format handling, budget-and-cancel checks before send, keys never written to disk, route identity (a relay is never recorded as official), two scorers, output caps and reuse keys. A frozen dual-model experiment (6 tasks × 2 models × 2 repeats) scripted through the protocol service before any real batch.

**Held-out case and gap closure (Phase 7)**
- A token-bucket held-out case (deficient variant over-capacity, fixed variant capped), and **K01–K03 closed in place:** credentials bind to the actual target (same name ≠ same target can't be reused), the attack-step budget is enforced at admission (one admit = one unit; retries don't recount; pause/resume don't refund), and gate conditions carry the three states with real detail.

**Security domain — real attack models, not an attack graph (Phase 8)**
- The earlier attack-**graph** abstraction (`compromised[step]`/`hardened[step]`) was **removed from the platform and the repository**. What replaced it is a **real attack model**: state is security posture (footholds, admin, stolen credentials, network reach, exfiltration), actions are techniques with genuine preconditions/effects, defences are model constants, and the attacker's goal is reached by a **Z3 plan**.
- **Two real CVEs as formal attack/defence models**, Z3 the ground truth: **Log4Shell** (CVE-2021-44228, Apache Log4j 2 — RCE reachable in 2.14.1, blocked in 2.16.0; any one of six single controls cuts the chain) and the **Struts/Equifax** breach (CVE-2017-5638 → recon → credential access → lateral movement → DB access → exfiltration; 12 controls, every stage two-branched so the minimum cut is two).
- **A live red–blue game** on the Struts/Equifax model: two frontier models plan attacker vs defender in real time with the formal model as referee, then switch sides. Reported honestly, refusals and forfeits recorded.
- **Model ↔ reality (verified).** The vulnerable versions were deployed to an isolated Kubernetes namespace and the running artifacts confirmed by **read-only** administrative inspection; the configurations match the models' `vulnerable` preconditions exactly, so the Z3 verdicts apply to the real deployment. Detection follow-through shipped as importable **Sigma** (3 rules) and **Suricata** signatures. Offensive artifacts are kept local and git-ignored, out of version control.
- **Refusal sensitivity to framing (`cyber-rename`).** The same two CVE models, posed four ways with identical structure and shared Z3 truth, over the **official** claude-opus-5-5 route: refusal rate **attackmodel 0.50 < abstract 0.67 < logistics 0.75 < anchored 1.00**. A disguised "logistics" rename and a generic "defensive security exercise" preamble both *raised* refusals; only grounding in a real named CVE lowers them. Every answered unit is Z3-correct. A robustness / false-refusal result, not a jailbreak. Write-up: `docs/security/refusal-sensitivity-cyber-rename.md`.
